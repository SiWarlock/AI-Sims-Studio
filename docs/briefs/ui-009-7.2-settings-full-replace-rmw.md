# /tdd brief — settings_full_replace_rmw

## Feature
**Correctness fix (data-loss).** The user pinned `ARCHITECTURE.md §4` `PUT /settings` = **FULL-REPLACE** (REST-standard,
not PATCH-merge). The shipped settings write helpers do a **partial PUT** (one field), which under full-replace
**silently resets the omitted sibling field** — e.g. saving a Mods path wipes `telemetryEnabled`, and toggling
telemetry wipes `simsModsPath`. Rework both helpers to **read-modify-write the full `SettingsResponse`**, switch the
mock fixture to full-replace, and invert the tests — atomically, so the mock stops masking the contract.

## Acceptance criteria (what "done" means)
- [ ] A read-modify-write path: each settings write **reads current settings (GET), applies the one changed field in
      memory, and PUTs the FULL object** (`{ simsModsPath, telemetryEnabled }` — both fields always present).
- [ ] `persistModsPath(client, modsPath)` → reads current, sets `simsModsPath`, PUTs full; preserves the current
      `telemetryEnabled`.
- [ ] `persistTelemetryEnabled(client, enabled)` → reads current, sets `telemetryEnabled`, PUTs full; preserves the
      current `simsModsPath`.
- [ ] `test/fixtures/mock-settings.ts` is **full-replace**: PUT replaces stored settings with the body, **resetting any
      omitted field to its default** (`simsModsPath`→`null`, `telemetryEnabled`→`false`) — so a partial PUT regression
      is caught, not masked.
- [ ] Tests **inverted**: the PUT body now contains **both** fields; a **GET precedes the PUT** (read-modify-write);
      the sibling field survives a single-field update **because of the read-modify-write**, not mock merge.
- [ ] rule-5 preserved: no secret on the PUT body (only `simsModsPath`/`telemetryEnabled`).
- [ ] All `test/settings/settings.test.ts` pass; `/preflight` clean.
- [ ] No cross-doc invariant change in code (the §4 arch-note + the `UpdateSettingsRequest` footgun flag are
      orchestrator/ledger routing — see below).

## Things to flag at Step 2.5
1. **Shared `writeSettings(client, patch)` helper vs. two independent read-modify-writes.** My default vote: **shared
   private helper** — GET current → spread `patch` over it → PUT the full object; both public helpers delegate. One
   correct read-modify-write path, no duplication, impossible to forget a field.
2. **Mock full-replace reset defaults.** Omitted `simsModsPath`→`null`, omitted `telemetryEnabled`→`false`. My default
   vote: **model full-replace faithfully** (omitted = default) so a partial-PUT regression fails loudly.
3. **Read-modify-write TOCTOU race.** A GET→PUT window exists. My default vote: **accept + document** — onboarding
   settings are single-user/low-contention; optimistic concurrency is a future concern, not this fix. (Do NOT
   over-engineer.)
4. **`telemetryEnabled` default on reset.** The contract has no explicit default; I'm asserting `false`
   (privacy-first — telemetry off unless opted in). My default vote: **`false`**. If you read a different intended
   default from the contract/§18, flag it (it's a mock-fidelity choice, not shipped behavior — the real default is the
   Phase-2 handler's, tracked by the §4 pin).
