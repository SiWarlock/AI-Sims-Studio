# /tdd brief — langgraph_stategraph_checkpointer

## Feature
The resumable LangGraph **StateGraph spine** for the pipeline sidecar: a typed `PipelineState`, one node/subgraph per stage (plan → concept → mesh → overlay → export) with the **5 ordered approval gates** as `interrupt()`/`Command(resume)`, and a **checkpointer factory** (Postgres primary, SQLite saver fallback) that is **provably resumable across a process restart** — on mock/no-op stage bodies (real generation lands 2.2+).

## Use case + traceability

- **Architecture sections it implements:** `ARCHITECTURE.md §5` (LangGraph orchestration: typed State, interrupt() gates, checkpointer ownership-partition, ADR-002 parity), `ARCHITECTURE.md §12` (domain state model — State references §12 entities by id, does not redefine them).
- **Related context:** the ADR-002 open question (`langgraph-checkpoint-postgres` parity vs the SQLite saver = a build-start verification). 0.7 store skeleton (`store/models.py` owns `PipelineRunRow`/`StepRow` — the **app repository**, distinct from the checkpoint). 0.4a frozen domain enums in `aisims_contracts` (`ItemState`, `StepState`, `GateKind`). Phase-2 acceptance items (Inv1, Inv5) in `IMPLEMENTATION_PLAN.md` "Acceptance criteria (2)".

## Acceptance criteria (what "done" means)
- [ ] `build_graph(checkpointer)` compiles a `StateGraph` over a typed `PipelineState` with one node per stage in order: **plan → concept → mesh → overlay → export** (stage bodies are no-op placeholders in 2.1 that advance State; real cloud/two-phase logic is 2.2).
- [ ] `PipelineState` is a typed **Pydantic v2** model that references domain entities **by id** (`projectId: str`, `runId: str`, per-item `dict[str, ItemState]` status map, `providerJobRefs`, a `gateCursor: GateKind | None`) and **imports** `ItemState`/`StepState`/`GateKind` from `aisims_contracts` — it does NOT redefine §12 entities (§5 "State references domain entities by id").
- [ ] Each of the 5 gates pauses via `interrupt(payload)`; resuming with `Command(resume=<decision>)` continues from the paused position (gate decision surfaces on the stream's interrupts).
- [ ] A **checkpointer factory** (`make_checkpointer(...)`) selects `langgraph-checkpoint-postgres` (PG) as primary and **falls back to the SQLite saver in a separate path/module** when PG is unavailable, **logging** the fallback (ADR-002). SQLite saver = the deterministic unit path; the PG path is **env-gated behind `AISIMS_TEST_DATABASE_URL`** (mirrors the 0.7 test-DB strategy).
- [ ] **Resume-across-restart (the core contract):** a run interrupted at a gate, checkpointed under a `thread_id`, resumes from the last checkpoint when the graph is **re-instantiated from a fresh builder + a fresh saver bound to the same store** (simulating process restart) — completed nodes are NOT re-executed.
- [ ] **[SAFETY-RULE-6 · Inv5 · D16 · OWN COMMIT]** Ordered-gate pin: a test asserts gates fire only in `plan→concept→mesh→overlay→export` order — no mesh gate before concept-approved, no overlay before mesh, no export before overlay; an **out-of-order resume is rejected**. `GateKind` (from `aisims_contracts`) is the canonical enum.
- [ ] All unit tests in `services/pipeline/tests/graph/` pass; the env-gated PG-saver test skips cleanly when `AISIMS_TEST_DATABASE_URL` is unset.
- [ ] `/preflight` clean (`ruff` + `mypy --strict` + `pytest`).

## RED test outline (Step 2)
Tests in `services/pipeline/tests/graph/`:

1. **`test_pipeline_state_references_entities_by_id`** (`test_state.py`) — Asserts: `PipelineState` validates with id-typed fields + an `ItemState` status map; constructing it with a full embedded `ItemSpec` body is NOT the shape (by-id only). Why: §5 "State references domain entities by id, does not redefine them."
2. **`test_pipeline_state_imports_contract_enums`** (`test_state.py`) — Asserts: `PipelineState`'s gate cursor field is the `aisims_contracts.GateKind` enum (identity import, not a redefined local enum). Why: §12 single-source enums; avoids a duplicated-contract forbidden pattern.
3. **`test_build_graph_has_five_ordered_stage_nodes`** (`test_build.py`) — Asserts: the compiled graph exposes nodes for plan/concept/mesh/overlay/export wired in that linear order (START→plan→…→export→END). Why: §5 "one node/subgraph per stage" + the ordered pipeline.
4. **`test_each_gate_interrupts`** (`test_build.py`) — Asserts: streaming a run with an in-memory/temp saver pauses at the plan gate with an `interrupt` payload; `Command(resume=...)` advances to the next gate. Why: §5 gates = `interrupt()`/`Command(resume)`.
5. **`test_make_checkpointer_prefers_pg_falls_back_to_sqlite`** (`test_checkpointer.py`) — Asserts: with no/invalid PG URL, `make_checkpointer` returns the **SQLite saver** and logs the fallback; with a valid `AISIMS_TEST_DATABASE_URL` it returns the **PG saver** (this branch `@pytest.mark.skipif` when unset). Why: §5 / ADR-002 "fall back to SQLite checkpointer in a separate file if unavailable."
6. **`test_checkpointer_parity_resume`** (`test_checkpointer.py`) — Asserts: the same minimal graph run, interrupted then resumed, yields **identical final State** under the SQLite saver and (env-gated) the PG saver. Why: ADR-002 parity verification.
7. **`test_resume_across_simulated_restart`** (`test_resume.py`) — Asserts: run → interrupt at a gate → **drop the graph+saver, rebuild both** against the same SQLite file + `thread_id` → `Command(resume=...)` continues from the checkpoint; a spy/counter confirms pre-gate nodes did NOT re-execute. Why: §5 "survive process exit" — the resumability contract.
8. **`test_gates_strictly_ordered`** (`test_gates_ordered.py`) — **[Inv5 SAFETY PIN]** Asserts: (a) the happy path admits gates only in plan→concept→mesh→overlay→export order; (b) a `Command(resume)` that targets a later gate before the prior gate's approval is **rejected** (raises/no-advance). Why: SAFETY-RULE-6 / Inv5 (§5 ordered gates), D16-pinned.

## Things to flag at Step 2.5
1. **Checkpointer parity strategy (ADR-002).** (a) runtime probe: try PG, fall back to SQLite, parity asserted by running the same graph through both savers; (b) explicit config-flag selection; (c) PG-only with SQLite only in tests. **My default vote: (a)** — matches §5 "fall back to SQLite checkpointer in a separate file if unavailable" + the 0.7 deterministic-SQLite-unit / env-gated-PG split. Keeps unit tests Docker-free.
2. **`PipelineState` granularity.** Carry per-item sub-state inline, or only ids + a pointer to store rows? **My default vote: ids + status enums inline, entity bodies by-ref in the store** — §5 ownership partition: the checkpoint is graph-position-authoritative ONLY; the app repository (0.7 `PipelineRunRow`/`StepRow`) owns entity rows. State stays lean (ids + `dict[str,ItemState]` + job refs + gate cursor).
3. **Stage-node bodies in 2.1.** Real mock-adapter calls or pure no-op placeholders? **My default vote: pure no-op placeholders that advance State** — real provider / two-phase cloud-node logic is **2.2**; 2.1 proves topology + gates + checkpointer resumability, not generation. (Don't import `adapters/mock` here — keeps the layer boundary clean.)
4. **Inv5 enforcement mechanism.** (a) graph topology only (edges allow just the ordered path), or (b) topology **+ an explicit ordered-gate guard** that rejects an out-of-order `Command(resume)`. **My default vote: (b)** — topology gives the happy path; the guard is what the Inv5 test pins (a resume targeting a later gate before the prior approval is rejected). The guard is `GateKind`-keyed and lives in `gates.py`.
5. **`durability` at compile.** Set `durability='sync'` now, or defer the tuning to 2.2? **My default vote: `durability='sync'` for the gate-bearing graph** (§5: sync for cloud/long stages) — the gate-resume contract wants checkpoints to survive process exit; the cheaper `exit`/`async` tuning for deterministic-only stages can come with 2.2's cloud node. Flag if the langgraph version surfaces `durability` only at `stream`/`invoke` rather than `compile`.
