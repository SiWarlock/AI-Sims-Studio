## Feature
The sidecar-side keychain **read** accessor — a NEW class `KeychainSecretsAccessor` implementing the **structural
`SecretsAccessor` Protocol** (`services/pipeline/obs/secrets.py`: `get(name)→str|None`, `active_values()→
tuple[str,...]`) in a NEW file `services/pipeline/obs/keychain_secrets.py`, reading provider API keys from the OS
keychain via Python **`keyring`** at **`service="AISimsCreator"`, `account=<providerId>`** — the SAME named entry
the UI writes (7.2b-1, interop proven by spike 7.2b-0). **Zero edits to existing pipeline files** (per F2=B/ASK-2).
Mock-first: the `keyring` backend is injected so unit tests touch no real keychain. Boot-time selection of this
accessor (vs the Phase-0 `InMemorySecretsAccessor`) is a **Phase-2 supervisor TODO** — out of scope here.

## Acceptance criteria (what "done" means)
- [ ] **Reads the locked-in named entry.** `KeychainSecretsAccessor.get(providerId)` returns
      `keyring.get_password("AISimsCreator", providerId)`; an absent key → `None` (not an error).
- [ ] **`active_values()` returns live values for the redactor.** Over the injected backend, returns the tuple of
      the configured providers' current values (skipping any absent), so the §16 redactor can scrub them.
- [ ] **Implements the Protocol structurally** — `KeychainSecretsAccessor` satisfies `SecretsAccessor`
      (`get`/`active_values` signatures match); a `mypy --strict` assignment to a `SecretsAccessor` variable holds.
      **Zero edits to `obs/secrets.py`** or any existing pipeline file.
- [ ] **Rule-5 redaction.** `repr`/`str` expose **names only, never values** (mirror `InMemorySecretsAccessor`);
      the key value appears in no log/repr/exception surface (redaction-canary test).
- [ ] **Shared-contract pin.** The service constant == `"AISimsCreator"` (matches the UI writer's `KEYCHAIN_SERVICE`).
- [ ] **Mock-first.** Unit tests inject the `keyring` backend (no real keychain); `keyring` unavailability surfaces
      a typed/handled path, not a bare crash.
- [ ] `/preflight` clean (ruff + `mypy --strict` (packages?/pipeline) + pytest) in `services/pipeline/`.

## Things to flag at Step 2.5
1. **`active_values()` enumeration — injected provider-id set vs keyring enumeration.** `keyring` has no portable
   enumeration, so **Default: construct with an injected `Iterable[str]` of active provider ids** (the sidecar's
   configured providers; Phase-2 supplies the real list). `active_values()` reads each. Confirm.
2. **Injected backend seam.** **Default:** a constructor param (e.g. `get_password: Callable[[str,str],str|None]`
   defaulting to `keyring.get_password`) so tests pass a fake; the real `keyring` is the prod default. Mirrors the
   7.1/7.2c native-boundary injection.
3. **`keyring` unavailability.** **Default:** surface a typed/redacted handled path (don't crash the accessor); the
   §16 redactor must still function (fail-safe). Confirm whether a missing key vs an unavailable backend need to
   differ (likely: missing→None, unavailable→typed-handled).
4. **mypy area.** This is `services/pipeline/` — run its `mypy --strict` + ruff + pytest (the pipeline area's
   `/preflight`), not the desktop one.
