# /tdd brief — preload_fs_bridge

## Feature
Make 7.2a's Sims-install detection **actually functional** in the real app: the Electron **main process**
performs the four read-only filesystem probes (`exists` / `isDirectory` / `isWritable` / `homeDir`), the
**preload** exposes them to the renderer under `window.aisims.fs` over a **narrow synchronous bridge**
(`sendSync`, consistent with the 7.1 token handoff — Lesson 3), and 7.2a's already-shipped `resolveFsProbe`
(which shape-guards `window.aisims.fs` + safe-defaults) now resolves the **real** probe. No raw `node:fs` is ever
exposed to the renderer — only the four read-only boolean/string probes (no file-content read, no write).

## Things to flag at Step 2.5
1. **Sync (`sendSync`) vs async probes.** The 7.2a `FsProbe` interface is **synchronous**; backing it with
   `sendSync` keeps detection/validation unrippled (consistent with the 7.1 token handoff, Lesson 3). The
   alternative — async probes — would force `FsProbe` + `detectSimsInstall`/`validateModsPath` to become async
   (a 7.2a ripple). **Default: `sendSync`** (fast local probes; same posture as the token bridge). 
2. **Path-safety scope.** The four probes are read-only existence/stat/access checks the user needs for an
   arbitrary Mods location, so they accept any path; the security guarantee is **no content read + no write + no
   arbitrary method** (not path restriction). **Default: allow any path for the four read-only probes; pin that
   nothing beyond them is exposed.**
3. **`isWritable` mechanism.** `fs.access(path, W_OK)` (non-destructive) vs a temp-write probe. **Default:
   `fs.access(W_OK)`** — never write to the user's FS to test writability.
