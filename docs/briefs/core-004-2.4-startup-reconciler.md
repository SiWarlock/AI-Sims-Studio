# /tdd brief — startup_reconciler

## Feature
The **startup reconciler** (§6 decision-table): on reopen, for each persisted in-flight `ProviderJobRef`, poll the provider and route to **re-poll** (job alive), **re-fetch** (succeeded-but-artifact-missing → then regenerate if re-fetch fails), or **regenerate** (expired / GC'd / failed → step failed + offer regenerate). Plus **stale-lock recovery** — reclaim the single-writer lock from a **dead** owner PID on reopen. On mocks.

## Acceptance criteria (what "done" means)
- [ ] A pure **decision function** `decide(poll_status, artifact_present) -> ReconcileAction` implements the §6 table:
  - `submitted`/`running` → **RE_POLL** (job alive)
  - `succeeded` ∧ artifact present → **RESUME** (no-op; continue from here)
  - `succeeded` ∧ artifact missing → **RE_FETCH**
  - `failed`/`expired` → **REGENERATE** (step failed + offer regenerate)
- [ ] A `Reconciler.reconcile(refs, provider, artifact_exists)` driver polls each persisted `ProviderJobRef`, applies `decide`, and on a **RE_FETCH** whose re-fetch fails (urls expired) **escalates to REGENERATE** ("re-fetch then regenerate"). Returns a `dict[jobId, ReconcileOutcome]` (the per-ref resolution).
- [ ] **Stale-lock recovery:** on reopen, a lock held by a **DEAD** owner PID is **reclaimed**; a lock held by a **LIVE** PID is **NOT** reclaimed (wires the 0.9 `SingleWriterLock` dead-PID-only rule — no new fencing).
- [ ] **Per-ref failure isolation:** one ref's poll raising does not abort the reconcile of the others (mirrors the 2.3 scheduler discipline — catch `Exception`, not `BaseException`; Lesson 15).
- [ ] No `packages/contracts` change (cross-doc invariant: none). All unit tests in `tests/engine/test_reconciler.py` pass; `/preflight` clean.

## RED test outline (Step 2)
Tests in `tests/engine/test_reconciler.py`:

1. **`test_decide_pollable_re_polls`** — Asserts: `decide(SUBMITTED, *) == RE_POLL` and `decide(RUNNING, *) == RE_POLL`. Why: §6 "job_id pollable → re-poll."
2. **`test_decide_succeeded_artifact_present_resumes`** — Asserts: `decide(SUCCEEDED, artifact_present=True) == RESUME`. Why: §6 succeeded + present → continue.
3. **`test_decide_succeeded_artifact_missing_refetches`** — Asserts: `decide(SUCCEEDED, artifact_present=False) == RE_FETCH`. Why: §6 "succeeded-but-artifact-missing → re-fetch."
4. **`test_decide_expired_or_failed_regenerates`** — Asserts: `decide(EXPIRED, *) == REGENERATE` and `decide(FAILED, *) == REGENERATE`. Why: §6 "expired/GC'd → step failed + offer regenerate."
5. **`test_reconcile_refetch_then_regenerate_on_expired_urls`** — Asserts: a succeeded-but-missing ref whose re-`fetch()` fails (urls expired) escalates to **REGENERATE** in the outcome. Why: §6 "re-fetch then regenerate."
6. **`test_reconcile_per_ref_isolation`** — Asserts: a batch where one ref's `poll` raises → the other refs still resolve; the raising ref's outcome captures the error (catch `Exception`, Lesson 15). Why: per-ref failure isolation.
7. **`test_stale_lock_dead_pid_reclaimed_on_reopen`** — Asserts: a lock file owned by a **dead** PID is reclaimed on reopen; **`test_live_lock_not_reclaimed`** — a live-PID lock is NOT reclaimed (raises/blocks). Why: §6 dead-PID-only reclaim (0.9 rule).

## Things to flag at Step 2.5
1. **Ref sourcing — where the reconciler reads persisted refs.** From the langgraph checkpoint (awkward — graph-internal) vs a queryable app-repo store column (the 2.2-(d) follow-on) vs an input param. **My default vote: the reconciler takes `refs` as an input param (sourcing-agnostic) for 2.4** — the queryable app-repo persistence (a `StepRow`/job-ref store column, a store change not a contract change) is a thin follow-on for the live boot wiring. Keeps the decision-table testable now without a store schema change. Flag if you'd rather add the store column in-slice.
2. **"GC'd" simulation on mocks.** The mock `poll` has no "job-not-found"; the closest signals are `PollStatus.EXPIRED` and an injected POLL failure. **My default vote: treat `EXPIRED` (the Tripo-race signal) and an injected poll-failure both as the expired/GC'd → REGENERATE branch** — don't invent a new mock state.
3. **artifact-presence check.** **My default vote: an injected `artifact_exists(path) -> bool` predicate** (the reconciler checks the fetched path's presence; a callable for tests, a real `os.path.exists` at the boundary) — keeps the reconciler pure/testable and the FS dependency injected.
4. **Apply actions vs return them.** Does 2.4 *perform* the resolution (re-poll loop, re-fetch, DB "step failed" write) or return the decision map? **My default vote: 2.4 performs the mock-safe resolutions (re-poll, re-fetch) and RETURNS the outcome map** — the DB writes (mark step FAILED in a transaction) + the actual regenerate re-enqueue are the run-start integration via the repository. Don't add a `StepRepository` here (defer with the rest of the boot wiring).
5. **Lock reclaim — reuse `SingleWriterLock` as-is.** **My default vote: wire the existing 0.9 dead-PID-only reclaim** (no atomic-acquire / fencing token — those stay the documented Phase-2+ upgrade, Lesson 8). 2.4 just calls reclaim on reopen + pins the dead-vs-live behavior.
