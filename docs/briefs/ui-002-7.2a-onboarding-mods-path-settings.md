## Acceptance criteria (what "done" means)
- [ ] **Sims-install detection.** `detectSimsInstall(fs)` probes the standard macOS Sims 4 user locations and
      returns a structured result `{ userDataDir?, defaultModsPath?, detected: boolean }` — pure over an injected
      filesystem probe (no real FS in unit tests). A missing install yields `detected:false` with no throw.
- [ ] **Mods-path validation.** `validateModsPath(fs, path)` returns a structured verdict: **hard-fails**
      (blocking) when the path is missing / not a directory / not writable; **warns** (non-blocking) when it
      doesn't match the expected `…/The Sims 4/Mods` shape. Deterministic over the injected probe.
- [ ] **Settings persistence round-trips via the frozen contract.** `loadSettings(client)` reads
      `GET /settings` → `SettingsResponse`; `persistModsPath(client, path)` writes `PUT /settings`
      (`UpdateSettingsRequest.simsModsPath`) and the value round-trips. Uses the 7.1 token-bearing client; a
      request still carries `X-AISims-Token` (fp-3). Tested against a mock sidecar fixture.
- [ ] **Secrets never ride settings.** A guard/assert that `persistModsPath` / settings writes never place a
      secret in the `/settings` body (safety rule 5; `UpdateSettingsRequest` has no secret field — pin it).
- [ ] **React/Vite renderer mounts.** The Vite-built React root replaces the static placeholder; the Electron
      shell loads the built renderer; `bootstrapObserver` (7.1 SSE observer) still runs in the renderer (no
      regression — the 7.1 reconnect/observer tests stay green).
- [ ] **No durable pipeline state in the renderer** (fp-2): settings are read server-driven, not cached as
      authority.
- [ ] All unit tests in `apps/desktop/test/` pass; `/preflight` clean.

## RED test outline (Step 2)
Tests in `apps/desktop/test/`:

1. **`test_detect_returns_default_mods_path_when_user_dir_present`** — Asserts: with a probe where `~/Documents/Electronic Arts/The Sims 4` exists, `detectSimsInstall` returns `detected:true` + a `defaultModsPath` ending `/The Sims 4/Mods`. Why: §18 install detection.
2. **`test_detect_missing_install_no_throw`** — Asserts: empty probe → `{detected:false}`, no throw. Why: §18 graceful first-run.
3. **`test_validate_mods_path_hard_fails`** — Asserts: missing / non-directory / non-writable path → blocking verdict. Why: §18 Mods-path validation.
4. **`test_validate_mods_path_warns_on_shape`** — Asserts: a writable dir not matching `…/The Sims 4/Mods` → non-blocking **warn**, not a block. Why: §18 (accommodate custom setups without blocking).
5. **`test_load_settings_round_trips`** — Asserts: `loadSettings` parses `SettingsResponse{telemetryEnabled, simsModsPath}` from the mock sidecar. Why: §4 GET /settings.
6. **`test_persist_mods_path_puts_and_round_trips`** — Asserts: `persistModsPath` issues `PUT /settings` with `simsModsPath` and the value round-trips; the request carries `X-AISims-Token`. Why: §4 PUT /settings; fp-3.
7. **`test_settings_write_never_carries_a_secret`** — Asserts: the settings write body has no secret field (only `simsModsPath`/`telemetryEnabled`). Why: safety rule 5 (secrets never ride /settings).
8. **`test_observer_still_boots_under_react_root`** (regression) — Asserts: `bootstrapObserver` still wires client+SSE+projection when invoked from the React entry. Why: no 7.1 regression.
